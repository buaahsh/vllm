# YOCO expert tuning

This directory contains YOCO-only Triton tuning maps. W13 files use the name
`w13_E=<experts>,N=<intermediate>,K=<hidden>,device_name=<device>.json`.
W2 files use the name
`w2_E=<experts>,N=<output>,K=<input>,device_name=<device>.json` and are
generated by `benchmarks/kernels/benchmark_yoco_moe_w13.py --objective w2`.

W2 keeps the W13 `BLOCK_SIZE_M` so both GEMMs reuse the same expert assignment.
Generated candidates must be remeasured with `--benchmark-only-config`; token
buckets whose W2 gain does not repeat should retain the W13 baseline config.

For YOCO L3 TP4 on B200, run from the repository root:

```bash
.venv/bin/python benchmarks/kernels/benchmark_yoco_moe_w13.py \
  --kernel-source vllm/model_executor/layers/fused_moe/fused_moe.py \
  --seed-config vllm/model_executor/layers/fused_moe/configs/E=128,N=960,device_name=NVIDIA_B200.json \
  --w13-config vllm/model_executor/layers/fused_moe/configs/E=128,N=960,device_name=NVIDIA_B200.json \
  --objective w2 \
  --output vllm/model_executor/layers/fused_moe/experts/yoco_configs/w2_E=128,N=1024,K=960,device_name=NVIDIA_B200.json
```

For TP1, add `--intermediate-size 3840`. The regular W13 map is written to
`configs/E=128,N=3840,device_name=NVIDIA_B200.json`; the separate W2 map is
`yoco_configs/w2_E=128,N=1024,K=3840,device_name=NVIDIA_B200.json`.

## Fast decode on B200

`decode_w13_*.json` and `decode_w2_*.json` hold the small-M measurements.
They match exact token-row counts only: interpolation across nearby counts
regressed some skewed routing cases. Unlisted sizes use the existing lookup.
W13 and W2 retain the same M tile so they share one expert assignment.
Align bypasses these tuning maps.

`cutlass_decode_b200.json` contains six FlashInfer tactics: GEMM1 and GEMM2 for
64, 128, and 256 token rows in full single-token CUDA graphs. Multi-token
prefill and eager calls retain the prior backend selection. Standalone L3 BF16
Fast may use the cached decode tactics when the
FlashInfer cache loader accepts the recorded GPU/CUDA/library metadata and
the maximum captured graph size is at most 256. Other configurations retain
their prior backend policy; no online autotuning is required.

The runtime uses the scheduler's full token budget for FlashInfer's bucket
mapping. This keeps large prefill requests from being clamped into the final
decode bucket and accidentally using a decode tactic. The cache contains no
prefill entries. Weights retain the existing `[up, gate]` layout and do not
require an additional copy.

Set `additional_config.yoco_fast_decode_cutlass=false` to disable the new
CUTLASS decode selection while retaining Triton tuning and the prefill policy.
