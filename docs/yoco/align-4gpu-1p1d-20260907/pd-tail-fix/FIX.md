# YOCO Mooncake 1P1D 尾块与空传输通知修复

日期：2026-09-07。运行环境为四卡 Job `yoco-align-fast-vllm-vllm-train`，
TP1 Prefill 使用 B200 GPU4，TP1 Decode 使用 GPU5。

未经修复的 Mooncake 1P1D 在105项输出字节比较中通过93项。
2048-token输入的冷缓存和缓存命中都发生偏差：logits最大绝对差0.125，
hidden为0.0185546875，完整log-prob约0.249969482421875。
同一D服务绕过P及KV传输、直接计算完整输入时105项全通过；独立单实例复测也全通过。
这些对照把问题范围缩小到了P端KV的保留与交接。

YOCO共享KV的D需要从最终提示块的起点重算尾部。核心调度器已实现这一分块，
NIXL连接器也已有对应P端截断逻辑，但Mooncake缺少配套。P若计算到完整提示末尾，
可能已回收D重算尾部所需的滑窗历史。因此Mooncake现在与已有NIXL约定一致：

- P和D共同使用 `floor((prompt_length - 1) / block_size) * block_size` 作为远端前缀长度。
- P入队时截断到该边界，D保留原始提示和输入计数，在本地计算尾部。
- P截断操作记录状态，重复入队不会再次缩短；少于或等于一块的提示由D本地完成。
- 截断后的P暂时跳过前缀缓存读取，避免复用无法保留所需滑窗历史的缓存。这是正确性策略，
  会影响真实trace性能；本轮原始Align和GEMM候选都使用相同策略。

首版修复的首个33-token请求字节一致，但重复请求触发D的调度状态断言。
原因是本地已缓存前缀时，空pull仅用于通知P释放资源，D没有等待远端KV；
Mooncake仍把空pull的响应发布为D的接收完成事件。现在只有实际含目标块的pull在
所有远端任务完成后发布该事件，空pull继续完成P端释放通知。
早期中止的空pull也不会再通知已不处于等待状态的D请求。

最终修复共涉及一个生产文件 `mooncake_connector.py`。原始失败案例及第一版失败日志
均保留，未修改预期张量。新增16项边界、重复入队和空pull测试，连同既有Mooncake及HMA
测试，30项同步测试与8项异步测试全部通过。异步测试使用独立test-deps目录中的
`pytest-asyncio==0.24.0`；不计入推理或训练运行环境。

最终修复的 `pd-before-fixed-r1` 已完成105/105字节比较，覆盖33/129/512/2048及
15/16/17/31/32-token提示、cold/hit、每条连续8个实际输出位置。
比较hidden、BF16全量logits及FP32全量log-prob，使用原始字节而非容差或只比较argmax。
这证明这些已测输入和执行配置的一致性，不构成所有输入、并发形状或分布式拓扑的普遍保证。
原始Align与GEMM候选的llm-train联动和trace性能结果以主报告为准。
