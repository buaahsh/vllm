# Fast FP8 W2 独立调参

2026-09-15，`fhb-dev-9-18`，YOCO L3 step28000 / B200。

为小 M 的 routed-expert W2 使用独立配置，只调整输出分块、warp 数和
流水线深度。W13、已有路由布局、K 方向的 FP32 累加边界、FP8 scale 和
每个专家的 BF16 输出边界保持原样。训练实现不变。

## 选择与范围

| 输入 token 行数 M | W2 输出分块 N | Warps | Stages |
| ---: | ---: | ---: | ---: |
| 1 | 32 | 4 | 4 |
| 2 | 32 | 2 | 4 |
| 4 | 64 | 4 | 4 |

原配置为 `M16/N128/K128, warps4, stages3`。新配置保留 `BLOCK_SIZE_M=16`、
`BLOCK_SIZE_K=128`、`GROUP_SIZE_M=1` 和 `SPLIT_K=1`。量化仍为 block-128；
较小的输出分块只是让多个线程块读取同一组 scale，不改变分组量化规则。

仅在已验证的 Fast direct-FP8 激活路径、B200、Top-8 / E128、
W2 `3840→1024`、block-128 W8A8、TP1/DP1/EP1 下启用。已有
`yoco_fp8_decode_aligned` 门槛排除其他并行和 EPLB 配置。显式 kernel
配置覆盖、batch-invariant、未列出的 M、不同形状和设备保留原选择。
BF16/Align 不使用这张 FP8 表。普通较大 M 仍使用原 DeepGEMM 分派。

选择依据是实际 M；小 M prefill 调用也可能使用此表。M8 的扫描收益仅约
1%，保留原配置。M16 虽有单算子收益，两轮完整模型均回退，因此同样
保留原配置。没有对相邻 M 插值。

`VLLM_YOCO_FP8_W2_TUNING` 默认 `1`；设为 `0` 可恢复旧 W2 配置。
该开关参与编译缓存标识，应在重新建立 engine / CUDA Graph 前设置。
配置文件位于 `experts/yoco_configs/decode_fp8_w2_E=128,N=1024,K=3840,device_name=NVIDIA_B200.json`。

## 单算子扫描

同一 B200，从八个物理层捕获真实 checkpoint 权重和 W2 输入；输入来自
固定随机 BF16 激活的完整 Fast 前向。每张计时图轮流执行八层 W2，
避免仅反复访问单层的热权重。对每个 M 扫描 36 组配置，两轮打乱顺序
计时；JIT 和数值检查均在正式计时前完成。

| M | 原 W2 / µs | 扫描最优 / µs | 延迟变化 | 采用 |
| ---: | ---: | ---: | ---: | --- |
| 1 | 22.54 | 15.53 | −31.10% | 是 |
| 2 | 23.75 | 18.78 | −20.92% | 是 |
| 4 | 29.51 | 26.92 | −8.78% | 是 |
| 8 | 41.01 | 40.59 | −1.03% | 否 |
| 16 | 74.20 | 67.57 | −8.94% | 否：整模型回退 |

180 个形状/配置组合在八层捕获输入上的 W2 输出均与原配置逐位一致。
另外核对了独立反量化后的 FP64 matvec 参考。单算子收益不代表整模型收益。

## 验证与证据

64 项回归覆盖配置回退、保持 W13 字典不变、两种路由布局、非连续输入、
输出 padding、CUDA Graph 中输入/路由/scale 更新、独立 FP64 数值参考，
以及已有 FP8 scale/cache 和直接量化测试。

并封存于 `abba-v1-not-applied.tar`，不计入性能结论。最终接入使用已有
online FP8 正确传递的 direct-activation 策略作为 Fast 路径门槛。

工作区证据：`yoco_results/fp8-w2-tune-20260915-wxj0zn5z/`。
原始扫描、捕获输入、所选配置、测试 XML、完整模型结果、源码快照和
