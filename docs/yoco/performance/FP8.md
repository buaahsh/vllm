# Fast BF16 / block-128 FP8 性能表

最新开发：[直接FP8激活与Top-8 logits路由](fast-fp8-route-direct-20260910/REPORT.md)。已测小M激活量化链路1.48–1.59×、routed-expert链路约1.3%–4.1%加速；整模型Mooncake尚未重测。下面的吞吐值继续对应各自已归档源码。

最新精度对照：[BF16 / FP8 的 Mooncake 2× 同卡结果](fast-bf16-mooncake-f2-20260909/REPORT.md)。Fast BF16 **1238.79**、当前 Fast FP8 **1407.84** 输出 tok/s，FP8/BF16 **1.136×（+13.65%）**。BF16为本轮补测，FP8沿用此前同条件结果。公共路径复用前后的+0.46%是FP8内部比较，见下方历史记录。

本表记录 Fast block-128 FP8 的测量。最新对照使用通过数值验证的默认 FP8 配置；旧版显式 DeepGEMM 的内部优化记录保留在后文。量化设置、硬件和工作负载是比较条件的一部分。历史 BF16 的 [1×](THROUGHPUT.md)、[1.2×](THROUGHPUT_F1P2.md) 和 [W2](LOW_CONCURRENCY.md) 结果各自维护。

旧版内部优化说明与完整证据见 [Fast FP8 报告](fast-fp8-20260908/REPORT.md)。结果为共享节点诊断；吞吐包含请求全部完成的时间，固定 offered rate 不代表容量上限。

后文旧版 FP8 内部优化快照早于后续的[Fast FP8 适配](fast-fp8-compat-20260909/REPORT.md)。旧增幅不能归因于后续适配改动；各轮源码与比较对象分别记录。

旧版端到端结果没有检查生成 log-prob 的有限性；文本 hash 相同不能证明模型数值正确。后续回归先经过[适配报告](fast-fp8-compat-20260909/REPORT.md)中的数值门槛，再记录吞吐。

## 维护方法

每次优化只更新实际重测的 FP8 实现与工作负载，保留基线的测量日期、source hash、case 名称和原始结果。每轮写入新的报告与 case 目录，再更新本表；原始失败记录和历史报告保留。

正式数值使用已经排除初次编译开销的测量。冷启动/预热不足导致的超时和调度退化应另列，不能与编译缓存预热后的状态混算为 kernel 加速。记录每轮 DeepGEMM/Triton cache 的新增条目，检查服务端队列、GPU 错误及完整排空。
